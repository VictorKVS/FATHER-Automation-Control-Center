### BOOK·CRAFT MEDIA

- Зафиксирована оценка текущего MVP: **70–75%**, статус **MVP Candidate / In Development**.
- Подтверждены существующие контуры: текст, изображения, аудиофайл, микрофон, STT, TTS и голосовые пресеты.
- Найдены блокирующие дефекты:
  1. аудио может теряться при одновременно заполненном текстовом поле;
  2. голосовая команда не гарантирует изменение текста книги;
  3. озвучка всей книги и разделов не завершена;
  4. backend требует безопасного lazy-init клиента;
  5. синхронные AI-вызовы могут блокировать async API;
  6. нет единого проверенного Windows-запуска UI + backend;
  7. контрактные тесты не заменяют реальные API-тесты;
  8. публичный GitHub Pages не имеет развёрнутого HTTPS media backend.
- Решение: после сдачи MVP разработку не прекращать; следующий основной этап — внутренняя база книг, версий, персонажей, событий, связей и медиа.

### Новая продуктовая идея

Создана задача [Vibe-coding #1 — BOOK·CRAFT Comics & Short Video Factory](https://github.com/VictorKVS/Vibe-coding/issues/1).

Стартовая готовность самостоятельного модуля: **5%**.  
Цепочка: история → сценарий → раскадровка → комикс → озвучка → субтитры → YouTube/TikTok/Shorts.  
Публикация допускается только после ручного подтверждения.

### Коммерческий приоритет

До подтверждённых продаж серверы не приобретаются. Первые продуктовые направления:

1. **152-ФЗ Audit Assistant** — экспресс-диагностика, gap-анализ, роли, сроки, риски и план 30/60/90.
2. **OSINT Due Diligence** — доказательное досье контрагента или кандидата.
3. **Security Documentation Factory** — комплект документов под организацию.
4. **BOOK·CRAFT Media** — книги, комиксы и короткие видео.
5. **DevSafe** — защита кода и резервирование.
6. **FATHER** — внутренняя фабрика этих продуктов; не первый объект продажи.

### Архитектурные решения FATHER

- Кодовый каркас и прототипы собираются быстро; главный долгий актив — качественные базы знаний.
- Производство разделено на три контура:
  1. Knowledge Factory;
  2. Agent Competency Factory;
  3. Product Factory.
- Контекст модели не равен размеру базы: используется SQL-фильтрация → полнотекстовый/векторный поиск → граф → reranking → короткий доказательный контекст.
- Для ближайшего года предварительно заложено:
  - 100–200 ГБ на текстовые профессиональные базы;
  - около 100 ГБ на индексы, версии, тесты и журналы;
  - 500 ГБ–1 ТБ на изображения и аудио;
  - 2–4 ТБ на видео и резервные копии.
- Текущего ПК достаточно для MVP; серверный вопрос переносится до оплаченного пилота или устойчивой многопользовательской нагрузки.

## 4. Незавершённое и блокировки

### Локальный Git

На Windows зафиксировано незавершённое merge-состояние:

- ветки main и origin/main разошлись;
- конфликты исправлены;
- merge ещё требовал завершения коммитом;
- в PowerShell локальные CMD запускаются через префикс `.\`.

До получения нового кода необходимо завершить merge и проверить `git status`.

### Безопасность

В публичном `mindforge-ai-telegram-bot` обнаружен отслеживаемый `.env`. Содержимое не раскрывалось. До витрины необходимо:

- отозвать и заменить возможные ключи;
- удалить файл из HEAD и истории;
- добавить `.gitignore` и безопасный `.env.example`;
- проверить остальные публичные репозитории на секреты.

## 5. Зафиксированные команды Windows

Проверка и завершение merge выполняются осознанно после просмотра статуса:

```powershell
G:
cd "G:\1\Vibe coding\Vibe-coding"
git status
git diff --name-only --diff-filter=U
git commit -m "Merge origin/main and preserve BOOK CRAFT work"
git status
```

После завершённого merge:

```powershell
G:
cd "G:\1\Vibe coding\Vibe-coding"
git pull origin main
cd "DZ_6_WeWeb_Lovable"
.\START_BOOK_STUDIO.cmd
```

Примечание: перед финальной сдачей команда запуска должна быть заменена или дополнена единым проверенным launcher для UI + media backend.
