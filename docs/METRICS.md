# Метрики автоматических потоков и непрерывности разработки

## 1. Основные правила

- Метрика считается только по данным с определённым периодом измерения.
- Плановое и фактическое время хранятся раздельно.
- Неизвестное значение записывается как `null`, а не заменяется оценкой.
- Количество файлов, сообщений и коммитов само по себе не означает прогресс.
- Каждый процент должен иметь числитель, знаменатель и ссылку на исходные данные.
- Суточный период: 00:00–23:59 в зафиксированной временной зоне отчёта.

## 2. Время и прогресс

- `planned_stage_hours` — оценка трудоёмкости ограниченного этапа.
- `actual_runtime_hours` — только подтверждённое время запусков.
- `blocked_hours` — подтверждённое время блокировки.
- `recovery_time_minutes` — время от команды «открываем день» до подтверждённого плана и первого безопасного действия.

Прогресс этапа:

`progress_percent = passed_acceptance_weight / total_acceptance_weight × 100`

## 3. Метрики автоматических потоков

| Код | Метрика | Формула |
|---|---|---|
| AUT-01 | Использование мощности | `active_streams / total_capacity × 100` |
| AUT-02 | Выполнение команд | `commands_completed / commands_total × 100` |
| AUT-03 | Подтверждение команд | `commands_with_evidence / commands_total × 100` |
| AUT-04 | Ошибки команд | `commands_failed / commands_total × 100` |
| AUT-05 | Непроверенные команды | `commands_not_verified / commands_total × 100` |
| AUT-06 | Перенаправления | абсолютное число `redirect_count` за сутки |
| AUT-07 | Повторная работа | `rework_steps / completed_steps × 100` |
| AUT-08 | Green rate | `passed_acceptance_runs / all_acceptance_runs × 100` |

Команда со статусом `partial` не считается полностью выполненной.

## 4. Метрики суточного отчёта

| Код | Метрика | Формула | Цель |
|---|---|---|---|
| DAY-01 | Покрытие задач | `reported_tasks / detected_tasks × 100` | 100% |
| DAY-02 | Связь с репозиториями | `tasks_with_repository_url / reported_tasks × 100` | 100% либо объяснённое исключение |
| DAY-03 | Доказательность | `tasks_with_evidence_url / completed_tasks × 100` | 100% |
| DAY-04 | README coverage | `updated_project_readmes / changed_repositories × 100` | 100% |
| DAY-05 | Заполнение следующего шага | `tasks_with_next_action / unfinished_tasks × 100` | 100% |
| DAY-06 | Покрытие тестами | `changed_repositories_with_test_status / changed_repositories × 100` | 100% |
| DAY-07 | Потерянные задачи | `detected_tasks - reported_tasks` | 0 |
| DAY-08 | Просроченное закрытие | минуты от конца дня до сохранения отчёта | ≤30 минут |

`test_status` считается заполненным и при значении «тесты не запускались», если это указано явно.

## 5. Метрики восстановления

| Код | Метрика | Формула | Цель |
|---|---|---|---|
| REC-01 | Полнота восстановления | `restored_required_fields / required_fields × 100` | 100% |
| REC-02 | Время восстановления | `recovery_time_minutes` | ≤15 минут |
| REC-03 | Расхождения | число конфликтов между планом, реестром и GitHub | 0 необъяснённых |
| REC-04 | Потерянные команды | `issued_commands - restored_commands` | 0 |
| REC-05 | Повторно выполненные задачи | задачи, ошибочно запущенные второй раз | 0 |
| REC-06 | Помощь владельца | число уточнений, без которых нельзя восстановиться | 0 на MAX |
| REC-07 | Первый безопасный шаг | 1, если шаг сформирован и подтверждён; иначе 0 | 1 |

## 6. Индекс непрерывности

Все доли нормализуются от 0 до 100. Негативные метрики преобразуются в положительные оценки.

`continuity_score = 0.20×command_evidence + 0.20×task_coverage + 0.15×repository_linkage + 0.15×readme_coverage + 0.20×recovery_completeness + 0.10×test_status_coverage`

Индекс не может быть выше 69, если есть хотя бы одно из условий:

- потеряна команда владельца;
- потеряна задача;
- завершённая задача не имеет доказательства;
- изменённый репозиторий не указан в отчёте;
- продолжение может повредить или перезаписать непроверенные результаты.

## 7. Gate-уровни

### MIN — сохранность

- все команды владельца перечислены;
- все задачи дня перечислены;
- каждый изменённый репозиторий указан;
- причина остановки и следующий шаг записаны;
- потерянных задач и команд: 0;
- `continuity_score ≥ 70`.

### MED — доказательность

Выполнен MIN, а также:

- доказательность выполненных задач: 100%;
- README coverage: 100%;
- test status coverage: 100%;
- необъяснённых расхождений: 0;
- `continuity_score ≥ 85`.

### MAX — автономное восстановление

Выполнен MED, а также:

- другой GPT восстанавливает состояние без предыдущего чата;
- время восстановления ≤15 минут;
- уточнений владельцу для восстановления: 0;
- повторно выполненных задач: 0;
- первый безопасный шаг определён правильно;
- `continuity_score ≥ 95`.

## 8. Светофор дня

- `green` — MED или MAX пройден, критических потерь нет.
- `yellow` — MIN пройден, но доказательства, README или тестовые статусы неполны.
- `red` — MIN не пройден, есть потерянная команда/задача либо небезопасная точка продолжения.

## 9. Обязательный снимок метрик

В каждый суточный отчёт добавляется:

```yaml
metrics:
  period:
  automation_commands_total:
  automation_commands_completed:
  automation_commands_with_evidence:
  tasks_detected:
  tasks_reported:
  completed_tasks:
  completed_tasks_with_evidence:
  changed_repositories:
  updated_project_readmes:
  repositories_with_test_status:
  lost_commands:
  lost_tasks:
  unexplained_conflicts:
  recovery_time_minutes:
  owner_clarifications:
  continuity_score:
  gate: FAIL | MIN | MED | MAX
  integrity_status: red | yellow | green
```

## 10. Статусы потоков

- `active` — поток выполняет назначенную работу;
- `reserve` — мощность свободна;
- `paused` — работа сохранена, но запуск отключён;
- `redirected` — поток передан другой фабрике;
- `blocked` — продолжение требует внешнего решения;
- `completed` — этап прошёл приёмочный gate.
