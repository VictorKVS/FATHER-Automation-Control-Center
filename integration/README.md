# FATHER — направления и правила подключения

Реестр: [project-registry.json](./project-registry.json). Это **логическое** разделение, не перенос репозиториев.

## Инварианты

1. Один источник истины для общего документа, проекта или знания; ссылки через устойчивые ID.
2. Проект может принадлежать нескольким направлениям, не создавая копий.
3. Git хранит исходники и ревизии; библиотека — индекс, метаданные, происхождение и ссылки на артефакты.
4. API контракт версионируется; несовместимое изменение требует миграции.
5. Обновление общей зависимости проходит анализ влияния и интеграционные тесты.
6. Нет автоматической записи в существующие проекты при обнаружении рассинхронизации.
7. Статус `registered` не означает `connected`, `tested` или `production-ready`.

## Контрольные этапы

- **P0** Реестр направлений и проектов — выполнен (первичный набор).
- **P1** Обнаружение остальных Git и локальных проектов — не выполнено.
- **P2** Инвентаризация локальной библиотеки CyberED и сопоставление источников — не выполнено.
- **P3** Read-only API реестра и библиотеки — не выполнено.
- **P4** Git-проверка ревизий и матрица совместимости — не выполнено.
- **P5** Сквозные интеграционные тесты и панель статусов — не выполнено.

Не записывайте токены, пароли, секреты или содержимое закрытых документов в публичный реестр.
